# Merging the mobile layer into the main repository

This branch is the 1.2.10 snapshot (tag `baseline-import`) plus new files only. No
existing game file was edited. Check with:

```bash
git diff --stat baseline-import
```

Every line of that output must be under `assets/mobile/` or `mobile/`.

## What to copy

Copy these two directories into the main repository root, unchanged:

- `assets/mobile/` — runtime modules and stylesheets (served by `server/app.py` because
  everything under `assets/` is already allowed)
- `mobile/` — plan, this guide, integration script, sandbox and tests (not needed at runtime)

## The one integration step

```bash
node mobile/tools/integrate.cjs
```

It appends the modules listed in `mobile/modules.json` to the end of the `ui` list in
`bundle-manifest.json` (after `optional-ui.js`) and runs `node build-client.cjs`. It is
idempotent. `node mobile/tools/integrate.cjs --check` reports the current state without
changing anything.

Files that change as a result, all of them build outputs or the manifest:

| File | Change |
|---|---|
| `bundle-manifest.json` | three new entries at the end of `ui` |
| `assets/bundles/ui.js` | rebuilt, now contains the mobile modules |
| `kart_racer.html` | rebuilt, new version hashes in `KART_BUILD` |
| `assets/boot.js` | rebuilt (content unchanged unless `assets.js`/`boot.js` changed) |

Doing it by hand is equivalent: add the three paths from `mobile/modules.json` to the `ui`
array in that order, then run `node build-client.cjs`.

Not handled by the script, because the repository has no generator for it:
`deployment-manifest.json` must be regenerated by the release process so it lists the new
files and the changed checksums.

## If the main repository has moved on since 1.2.10

The layer depends on these surfaces of the game. If a later version changed one of them,
that is where to look first:

| Surface | Used for |
|---|---|
| `#touch button[data-k]` with `pointerdown/up/cancel/leave` listeners bound in `boot()` (`game.js`) | all driving input; the add-on dispatches synthetic pointer events on them |
| action names `up, down, left, right, drift, item` | key driver |
| `body.lobby`, `window.kartActiveTrack`, `#panel.on`, `#results[hidden]` | race state |
| `window.KartRaceDebug.current.speed` | tests only |
| `#settings-controls` and the `.pref-row` class | settings block |
| ids `#raceTelemetry`, `#rearIndicator`, `#camera`, `#gear`, `#home`, `#sp`, `#minimap`, `#fx`, `#sec`, `#tl`, `#tr`, `#dr`, `#qte`, `#qk` | HUD rearrangement on phones |
| `KartAssets.text`, `KART_BUILD.versions` | stylesheet loading with cache-busting |
| `document.documentElement.lang` (`de`/`en`/`fr`) | add-on strings |

Run the tests after merging (they copy the tree to a temp directory, integrate and serve it
there, and need Python 3.12+ and Playwright with Chromium):

```bash
node mobile/tests/controls.cjs
```

```bash
node mobile/tests/menus.cjs
```

## Turning it off

- Per device: Settings → Controls → touch controls "off", or open the game with `?mobile=0`.
- Completely: remove the three entries from `bundle-manifest.json` and rebuild. Nothing else
  references the modules.

## Optional follow-up in the game itself

Steering is emulated by toggling the digital left/right keys once per frame, because the game
has no analog input. If true analog steering is wanted later, this one-line change in
`update()` in `game.js` enables it (the add-on already publishes the value):

```js
// before
const tgt=((keys.left?1:0)-(keys.right?1:0))*(ctl?1:0);
// after
const analog=window.KartMobile?.controls?.steer;
const tgt=(analog?-analog:(keys.left?1:0)-(keys.right?1:0))*(ctl?1:0);
```

This is not applied on this branch and is untested. `KartMobile.controls.steer` is
-1 for full left and +1 for full right, the opposite of the game's `tgt`, hence the
minus sign. With the hook in place the pulse emulation in `mobile-controls.js` should be
switched off for the same frames. Note that `pl.steer` is sent to other
players, so test it in an online race.
